# AstrBot 运维监控

SSH 登录探活、HTTP/HTTPS 健康检查、SSH 采集 Linux 状态，并向指定群聊或个人私聊发送自定义告警。支持同时绑定多个群和个人。

## 安装与首次使用

需要 **AstrBot >= 4.10.4、< 5，Python >= 3.11**。

1. 在 AstrBot 插件管理页上传插件 ZIP 安装包；也可将解压后的插件文件放入 `data/plugins/astrbot_plugin_ops_monitor/`。
2. 确认 AstrBot 的 Python 环境已安装插件 `requirements.txt` 中的依赖。如果需要手动安装：`python -m pip install -r data/plugins/astrbot_plugin_ops_monitor/requirements.txt`。
3. 启用插件，在插件配置页的「监控项」中添加 SSH 或 HTTP/HTTPS 项，填写唯一 `id`、名称、目标与凭据。
4. 使用 **AstrBot 管理员账号**，在需要接收告警的群聊或与机器人的私聊中执行 `/ops bind`。可以绑定多个会话。
5. 执行 `/ops test` 验证实际消息推送，再执行 `/ops check <id>` 验证探测。
6. 修改配置后重载插件或执行 `/ops reload`。

插件通过 AstrBot 的会话标识 UMO 路由消息，不能只填群号或用户 ID。绑定命令会自动获取完整 UMO。平台需要支持 AstrBot 主动消息；平台接口接受发送不等于用户一定收到，首次使用务必在接收会话中确认测试消息。

个人接收告警：用 AstrBot 管理员账号私聊机器人，先发送 `/ops bind`，再发送 `/ops test`。只接收某个监控项时使用 `/ops bind server01`。也可以把目标私聊的完整 UMO 手动填入全局或单项 `recipients`；接收人不必是管理员，但绑定指令仍仅限管理员使用。

接入约定参考 [AstrBot 消息发送文档](https://docs.astrbot.app/dev/star/guides/send-message.html) 和 [配置文档](https://docs.astrbot.app/dev/star/guides/plugin-config.html)。

## 支持的监控

| 类型 | 检查内容 | 可告警事件 |
| --- | --- | --- |
| SSH | 完成 SSH 握手并认证登录，支持密码或私钥 | 登录失败、超时、主机密钥校验失败 |
| HTTP / HTTPS | GET / HEAD，预期状态码、自定义请求头、可选响应文本检查 | 状态码不符、超时、证书错误、内容不符 |
| SSH 状态采集 | Linux CPU、内存、指定磁盘、1 分钟负载、运行时长、累计网络流量 | 采集失败、CPU/内存/磁盘/负载超阈值 |
| 响应耗时 | 可选阈值，单位毫秒 | 整轮探测耗时超阈值，含 SSH 登录与采集 |

SSH 状态采集需要远端安装 `python3`，只运行固定的只读 Python 标准库脚本，读取 `/proc` 与文件系统信息，无需安装 agent。仅探活时关闭 `collect_metrics`，即可检查其他提供 SSH 服务的系统。

每个指标、每个磁盘、每个监控项分别计数。SSH 登录成功但采集失败会产生「状态采集」事件；此时 SSH 仍为在线。登录或采集失败时，无法观测的 CPU、磁盘等指标保持原告警状态，直到重新采集到正常值，避免误报恢复。

CPU 为约 0.25 秒采样的总体使用率；内存使用率扣除可用内存；磁盘使用率按 `used / (used + available)` 计算，包含保留空间的影响。负载阈值是绝对值，未按核心数归一化。网络展示累计流量。

## 告警策略

全局策略在 `defaults`，每个监控项可覆盖策略。默认：连续异常 **3 次**告警、连续正常 **2 次**恢复、异常持续时每 **1800 秒**再次提醒。

| 配置 | 含义 | 单项继承值 |
| --- | --- | --- |
| `trigger_times` | 达到 X 次异常后告警 | `0` |
| `count_mode` | `consecutive` 连续次数，或 `window` 窗口次数 | `inherit` |
| `window_size` | 窗口模式最近 N 次采样，要求 N ≥ X | `0` |
| `recovery_times` | 连续正常达到此次数后结束告警 | `0` |
| `repeat_interval` | 同一故障重复提醒间隔，秒；`0` 只发首次 | `-1` |
| `notify_recovery` | 是否推送恢复消息 | `inherit`，覆盖用 `on` / `off` |
| `alert_template` / `recovery_template` | 告警 / 恢复模板 | 空字符串 |

连续模式中，一次正常采样就会重置异常计数；已经触发的告警仍需要达到恢复次数才结束。窗口模式例如 `trigger_times=3, window_size=5`，`异常、正常、异常、正常、异常` 会触发告警。达到连续恢复次数时也会清空窗口，开始新一轮计数。

次数按**定时采样轮次**计算，不按接收会话数或内部连接重试次数计算。`interval=30`、`trigger_times=3` 时，持续故障通常约 60～90 秒被通知，另加探测和发送耗时；不是精确的持续时长计时器。手动 `/ops check` 不参与告警计数。

只有收到过该故障告警的会话才会收到对应恢复通知。发送失败在下一次相应异常或正常采样时重试，已成功的会话不因其他接收方失败而重复发送。故障消失后不补发过时的故障消息。

状态、各会话发送记录与最近 100 条通知结果保存在 `data/plugin_data/astrbot_plugin_ops_monitor/alert_state.json`。正常重启保留计数和重复提醒时间；修改某监控项配置或全局策略会重置受影响的告警状态。进程在平台已接受消息、状态尚未落盘的极短时间内崩溃，重启后仍可能重复一条消息。

## 临时屏蔽告警

维护或排查期间可临时关闭自动推送，支持全局或单个监控项：

```text
/ops mute 30m             全部监控屏蔽 30 分钟
/ops mute 2h server01     仅 server01 屏蔽 2 小时
/ops muted               查看当前屏蔽及到期时间
/ops unmute              提前解除全局屏蔽
/ops unmute server01     提前解除 server01 的屏蔽
```

不填时长的 `/ops mute` 默认屏蔽全局 2 小时（等同于 `/ops mute 2h`）。时长支持 `s` 秒、`m` 分钟、`h` 小时、`d` 天，可写 `1h30m`；纯数字按分钟，范围 1 秒到 30 天。再次设置同一范围会从当前时间重新计算到期时间。

屏蔽期间探活、状态采集、异常计数与恢复判断继续进行，**自动告警和恢复通知均不推送**；屏蔽影响该范围内的全部群聊与私聊接收方。已经提交平台的消息无法撤回，手动执行 `/ops test` 仍会发送测试消息。

到期无需重载插件，下一轮采样若仍异常且已达到告警条件，会重新提醒，包括 `repeat_interval=0` 的策略。屏蔽期间已恢复的故障不会在到期后补发告警或恢复消息。

屏蔽到期时间与告警状态一起持久化，重启或 `/ops reload` 后仍然有效。`/ops status` 会显示屏蔽范围与剩余时间。全局和单项屏蔽可以重叠：解除全局屏蔽不会移除单项屏蔽，解除单项屏蔽也不会绕过全局屏蔽；使用 `/ops muted` 查看所有有效范围。所有屏蔽命令仍仅限 AstrBot 管理员使用。

## 群聊与私聊路由

- `recipients`：全局接收会话列表，`/ops bind` 会追加当前群聊或私聊，不会覆盖其他接收方。
- 监控项的 `recipients` 非空时，使用此项专属接收会话；空列表继承全局。
- `/ops bind server01`：把当前群聊或私聊加入 `server01` 的专属接收列表。
- `/ops unbind`：从全局列表移除当前会话；不会移除其他监控项的专属绑定。
- `/ops unbind server01`：从该项专属列表移除当前会话。最后一个专属接收方移除后会恢复继承全局，而非禁用通知。
- 未配置任何接收会话时仍采样、计数。绑定生效后，仍持续的故障会在后续异常采样时告警。

## 自定义消息

例如在某个 HTTP 项配置：

```text
🚨 {name} 不可用，请值班同学检查！
{detail}
累计触发 {count}/{trigger_times} 次
{time}
```

告警模板 `alert_template` 和恢复模板 `recovery_template` 都支持以下占位符：

| 占位符 | 含义与取值规则 | 示例 |
| --- | --- | --- |
| `{id}` | 监控项的唯一 ID，对应配置中的 `id`，用于定位具体监控项。 | `server01` |
| `{name}` | 监控项的显示名称，对应配置中的 `name`；未填写名称时使用 ID。 | `生产服务器` |
| `{kind}` | 监控类型，取值为 `ssh` 或 `http`；HTTPS 监控也显示为 `http`。 | `ssh` |
| `{event}` | 本条通知对应事件的中文名称，例如服务可用性、CPU 使用率或某个磁盘的使用率。 | `CPU 使用率`、`磁盘使用率 /var` |
| `{event_key}` | 事件的内部标识，用于区分同一监控项下独立计数的不同事件，具体取值见下表。 | `cpu_percent`、`disk:/var` |
| `{detail}` | 本次采样的可读详情，包含故障原因、状态码或指标与阈值；恢复通知中显示本次正常采样的详情。 | `CPU 使用率 92%，阈值 85%`、`SSH 登录成功` |
| `{value}` | 当前事件在本次采样中的值：指标数值、延迟毫秒数或 HTTP 实际状态码；没有可用值时为空字符串。不会自动附加单位。 | `92`、`503`、`1250.5` |
| `{threshold}` | 当前事件的告警阈值；HTTP 可用性事件中为期望状态码列表。没有阈值时为空字符串，不会自动附加单位。 | `85`、`200,204`、`1000` |
| `{count}` | 当前事件的异常采样次数。连续模式为连续异常次数，窗口模式为最近 N 次采样中的异常次数；不是消息发送次数。恢复通知中为 `0`。持续异常时可能大于触发次数。 | `3` |
| `{trigger_times}` | 当前监控项生效的告警触发次数 X，已考虑单项覆盖和全局继承。与 `{count}` 配合可显示触发进度。 | `3`，组合为 `3/3 次` |
| `{time}` | 本次采样对应的北京时间，格式为 `年-月-日 时:分:秒 CST`；不是平台实际送达时间。 | `2026-10-31 23:00:00 CST` |
| `{duration}` | 当前一轮故障从首个异常样本到本次采样的时长，单位为整数秒。包括触发前的等待、恢复确认和临时屏蔽期间；不是服务器运行时长。 | `120`，可写为 `{duration} 秒` |
| `{status}` | 通知类型，告警模板中为 `告警`，恢复模板中为 `恢复`。 | `告警` |

事件标识与数值单位：

| `{event_key}` | 对应事件 | `{value}` / `{threshold}` 的含义 |
| --- | --- | --- |
| `availability` | HTTP/HTTPS 或 SSH 服务可用性 | HTTP 收到响应时为实际状态码 / 期望状态码列表；SSH 探活、连接超时等没有状态码的情况两者均为空。HTTP 内容校验失败时仍可显示实际状态码，失败原因看 `{detail}`。 |
| `collection` | SSH 登录后的 Linux 状态采集 | 两者均为空；采集成功或失败原因看 `{detail}`。 |
| `cpu_percent` | CPU 使用率 | 当前使用率 / 配置阈值，单位为百分比。 |
| `memory_percent` | 内存使用率 | 当前使用率 / 配置阈值，单位为百分比。 |
| `disk:<路径>` | 某个指定磁盘路径的使用率，例如 `disk:/`、`disk:/var` | 当前使用率 / 配置阈值，单位为百分比；每个路径分别计数。 |
| `load1` | 1 分钟负载 | 当前负载 / 配置阈值，均为未按 CPU 核心数归一化的绝对值。 |
| `latency` | 响应延迟 | 本轮探测耗时 / 配置阈值，单位为毫秒，包含 SSH 登录与采集耗时。 |

`{value}` 和 `{threshold}` 只描述**当前这一条事件**，不会一次性列出机器全部指标；恢复时它们也是最新正常采样的值，不是故障时的峰值。对于通用模板，优先使用自带说明和单位的 `{detail}`，避免给 HTTP 状态码等事件统一加上 `%`。

例如某次 CPU 告警的 `name=生产服务器`、`value=92`、`threshold=85`、`count=3`、`trigger_times=3`，模板：

```text
[{status}] {name}（{id}）
事件：{event}
详情：{detail}
触发：{count}/{trigger_times} 次
持续：{duration} 秒
时间：{time}
```

会将每个占位符替换为本条事件的实际信息；恢复通知中的 `{status}` 会变为 `恢复`，`{count}` 变为 `0`，`{detail}` 变为正常采样详情。恢复消息发送失败后重试时，`{time}`、`{duration}` 和指标值随新的正常采样更新。

只支持表中这些简单占位符，不支持属性访问、格式表达式或条件判断。需要显示花括号时用 `{{`、`}}`，例如 `{{name}}` 会原样显示为 `{name}`。模板是纯文本，不会执行代码。

## SSH 与 HTTP 配置

SSH 密码与 `key_path` 二选一，填写私钥时优先使用私钥；加密私钥可填 `key_passphrase`。路径必须对 **AstrBot 进程**可见，Docker 部署时挂载到容器内并填写容器内路径。

默认开启 SSH 主机密钥校验。将经核对的服务器公钥放入 AstrBot 运行用户的 `~/.ssh/known_hosts`，或在 `known_hosts` 中指定文件路径。非 22 端口条目应使用 `[host]:port` 格式。默认关闭 SSH agent 与本地 SSH config 的自动读取，连接只使用本项显式配置。

HTTP `expected_status` 支持 `200,204` 这样的英文逗号列表。`body_contains` 仅检查响应前 64 KiB，检查文本时使用 GET。HTTPS 默认验证证书；需要测试自签证书时可显式关闭 `verify_tls`。默认跟随重定向。

插件自身不监听端口。AstrBot 所在机器需要访问目标 SSH 端口（通常 22）和 HTTP/HTTPS 端口（通常 80/443）；目标安全组、防火墙需允许来自 AstrBot 的连接。SSH 状态采集账号只需读取系统信息和所配置磁盘路径，无需 root。

密码、私钥口令和请求头会保存在 AstrBot 插件配置中；插件不会将这些值或完整 URL 写进默认告警与运行状态文件。显示名称、模板和磁盘路径是用户主动选择展示的文本。

完整配置样例见 [config.example.json](config.example.json)，示例地址需要替换，接收会话建议通过绑定命令设置。

## 指令

全部指令仅限 **AstrBot 配置的管理员**，群管理员身份本身不授予权限。

| 指令 | 用途 |
| --- | --- |
| `/ops` 或 `/ops status` | 最近采样概览、配置错误 |
| `/ops status server01` | 某监控项详情与指标 |
| `/ops check server01` | 立即检查，不增加告警次数 |
| `/ops bind [id]` / `/ops unbind [id]` | 绑定 / 解除当前群聊或私聊，全局或单项 |
| `/ops umo` | 获取当前会话 UMO |
| `/ops test [id]` | 实际测试全局或单项接收会话 |
| `/ops history` | 最近 10 条通知发送结果 |
| `/ops mute [时长] [id]` | 临时屏蔽全局或单项自动通知，默认 2 小时 |
| `/ops unmute [id]` | 提前解除全局或单项屏蔽 |
| `/ops muted` | 查看当前屏蔽与到期时间 |
| `/ops reload` | 重载配置 |
| `/ops help` | 帮助 |
